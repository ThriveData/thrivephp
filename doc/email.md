# Email

The email classes live in `ThriveData\ThrivePHP\Email`. Direct delivery uses PHP's
cURL extension. The queue uses the pgsql extension and PostgreSQL 14 or newer.
Attaching files by path also requires the fileinfo extension.

## Database setup

`postgres/provision.sql` includes the email schema. To add email support to an
existing application database, run the standalone installer:

```sh
psql "$DATABASE_URL" -v ON_ERROR_STOP=1 --single-transaction -f postgres/email.sql
```

It creates `email_address` and `email_contact`, the `email`, `email_contacts_types`,
`email_contacts`, and `email_files` tables, the `email` enqueue procedures, and the
retry trigger in the `public` schema. The installer can be run again.

## Settings

Add these keys to the application's settings:

```json
{
  "email": {
    "from": "Example sender",
    "connections": {
      "default": {
        "host": "smtp.example.com",
        "port": 587,
        "user": "sender@example.com",
        "password": "your-password",
        "secure": "tls"
      }
    }
  },
  "pgsql": {
    "connections": {
      "default": "host=localhost dbname=app user=app"
    }
  }
}
```

Use `tls` for STARTTLS, usually on port 587, or `ssl` for implicit TLS, usually on
port 465. The SMTP username supplies the default sender address. An explicit
`from` overrides it.

## Compose and queue

```php
use ThriveData\ThrivePHP\Email\{Contact, Email, MIMEFile};

$email = new Email(
    to: new Contact('recipient@example.com', 'Recipient'),
    subject: 'Your report',
    plain: 'Your report is attached.',
    html: '<p>Your report is attached.</p><img src="cid:logo">',
    headers: [
        'X-Request-ID' => 'request-123',
        'Message-ID' => '<request-123@example.com>',
    ],
    files: [
        '/path/to/report.pdf',
        new MIMEFile('notes.txt', 'Report notes', 'text/plain'),
    ],
);

$email->message->file('/path/to/logo.png', 'inline', ['Content-ID' => '<logo>']);
$email->message->attach('data.bin', $binaryBytes);
$email->message->header('X-Department', 'Accounts');
$email->queue();
```

Recipients accept an address string, a `Contact`, a `ContactList`, or an array of
strings and contacts. `cc`, `bcc`, and `reply` accept the same forms. BCC addresses
are included in the SMTP envelope but are not rendered as message headers.

Headers are an associative array of names and string values. `header()` also
accepts a complete `Name: value` line. MIME structure, sender, subject, recipient,
date, and mailer headers are generated by `Message::content()`.

`files` accepts file paths and `MIMEFile` objects. Paths are read while composing
the message. `queue()` stores the contents in `email_files.data` as binary `bytea`,
alongside each file's order, filename, MIME type, disposition, and custom headers.
Deleting or changing the original file after enqueueing does not affect delivery.
Inline files go in the multipart/related section; downloads go in multipart/mixed.
Order is preserved within each section.

Message headers live in `email.headers`. A single database call saves the message,
contacts, headers, and attachments. If any insert fails, PostgreSQL rolls back the
entire call. Attachment data travels in JSON as base64 and is decoded for storage.

## Send

For immediate delivery:

```php
$email->send();

// An explicit configuration is also supported.
$email->send(new \ThriveData\ThrivePHP\Email\SMTP\Config(
    host: 'smtp.example.com',
    user: 'sender@example.com',
    password: 'your-password',
    port: 587,
));
```

Run the queue worker from an application command after initializing settings:

```php
\ThriveData\ThrivePHP\Email\Queue::send();
```

Use one worker at a time. Each call processes due, unsent messages below their
attempt limit. The default maximum is four attempts. The retry trigger schedules
the next attempt at the creation time plus the square of the attempt count in
hours. A successful delivery sets `sent` and clears `attempted_next`. Headers and
attachment contents remain in the database for retries and inspection. Deleting
the email also deletes its contacts and files.

## SQL callers

The original JSON and typed-contact `public.email` signatures remain available.
The JSON signature accepts header objects; the typed signature accepts a `text[]`
of complete header lines. To enqueue attachments, use the seven-argument JSON
signature with `sender`, `contacts`, `subject`, `plain`, `html`, `headers`, and
`files`. Each file object has `filename`, base64 `data`, and optional `type`,
`disposition`, and `headers` fields. Pass `{}` for empty headers and `[]` for no
attachments.

## Verification

```sh
php -d short_open_tag=1 test/email.php
```

The queue test requires an empty disposable database with `postgres/email.sql`
installed. It writes test messages and exercises real database round trips,
rollback, and retries. It replaces SMTP transport with a test double, so it sends
no email.

```sh
EMAIL_TEST_DSN='host=localhost dbname=email_test user=app' \
    php -d short_open_tag=1 test/email-queue.php
```
